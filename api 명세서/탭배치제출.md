# **👉 Description**

클라이언트가 누적한 탭(연타) 배치를 서버에 제출하는 API입니다. **30초 또는 100탭 중 먼저 도달하는 시점**마다 호출하는 것을 전제로 설계되었습니다.

서버는 클라이언트가 보낸 `submittedCount`를 그대로 신뢰하지 않고, 최소 클릭 간격·분당 상한·일일 상한·배치 도착 간격 기반 봇 탐지를 거쳐 실제로 인정할 탭 수(`acceptedCount`)를 다시 계산합니다. 유효 탭이 누적되어 내부 목표치에 도달하면 포인트(P)와 키캡 상자가 자동으로 지급됩니다.

응답에는 이번 배치에서 인정된 탭 수(`acceptedCount`)뿐 아니라, 오늘(당일) 누적으로 인정된 총 탭 수(`validTapCount`)도 함께 반환됩니다. `validTapCount`는 세션 단위가 아니라 서버 기준 오늘 하루 전체 누적값으로, `GET /api/tap/today`의 `validTapCount`와 동일한 값이며 매 배치마다 갱신된 값을 즉시 확인할 수 있습니다.

같은 `tapSessionId` + `sequence` 조합으로 재전송하면 **멱등 처리**되어 중복 지급되지 않고, 그 시점의 잔액과 오늘 누적 인정 탭 수(`validTapCount`) 스냅샷만 반환합니다.

> ⚠️ 다음 **포인트** 지급까지 남은 탭 수(목표치)는 **의도적으로 이 응답에 포함하지 않습니다** — 적립 시점을 예측하지 못하게 하기 위한 정책입니다. (남은 탭 수는 `GET /api/tap/today`에서 확인 가능. 단, 오늘 누적 인정 탭 수 자체는 `validTapCount`로 노출되며, 이 정책은 "다음 포인트 목표까지 남은 수"만을 비공개로 유지합니다.)
>
> 반면 **상자** 목표치는 프론트의 낙관적 업데이트(탭마다 즉시 화면 갱신)를 지원하기 위해 `boxProgressTapCount`/`nextBoxRequiredTapCount`로 이 응답에도 노출합니다. `GET /api/keycap-boxes/status`, `GET /api/tap/today`와 동일한 값입니다.

# 👉Request Header

| name | type | description |
| --- | --- | --- |
| Content-Type | String | application/json |
| Authorization | String | accessToken (type: Bearer) |

# 👉Request **Body**

| name | type | requiered | Description |
| --- | --- | --- | --- |
| tapSessionId | UUID(String) | true | 클라이언트 탭 세션 식별자. 같은 세션 내 배치 순서 구분 및 멱등키의 일부로 사용 |
| sequence | Long | true | 세션 내 배치 순번(0 이상). `tapSessionId`와 조합해 멱등키로 사용됨 |
| submittedCount | Integer | true | 이번 배치에서 클라이언트가 집계한 탭 개수(1 이상). **부스터가 활성 상태인 동안에는 클라이언트가 실제 클릭 수의 2배로 계산해서 전송해야 함**(1클릭=2탭 정책, `GET /api/boosters/current`의 `active`로 확인). 서버는 이 값을 배율 계산 없이 그대로 신뢰하므로, 배가 책임은 전적으로 클라이언트에 있음 |

```json
{
    "tapSessionId": "b3f1c2a0-1234-4a5b-9c3d-abcdef123456",
    "sequence": 5,
    "submittedCount": 87
}
```

# **👉 Response**

### ✅ **성공 응답 예시**

### **Response Code**

`200`

### **Response Body**

| name | type | Description |
| --- | --- | --- |
| acceptedCount | Integer | 서버가 검증 후 유효하다고 인정한 탭 개수(봇 의심 시 0으로 반영될 수 있음) |
| validTapCount | Integer | 오늘(당일) 누적 인정 탭 개수. 세션 단위가 아니라 서버 기준 오늘 하루 전체 누적값이며, 여러 세션에 걸쳐도 날짜가 같으면 계속 누적됨(`GET /api/tap/today`의 `validTapCount`와 동일한 값) |
| pointsAwarded | Integer | 이번 요청 처리로 새로 지급된 포인트 개수 |
| boxesDropped | Integer | 이번 요청 처리로 새로 지급된 키캡 상자 개수 |
| balance | Long | 처리 후 현재 포인트 잔액 |
| pointDailyCapReached | Boolean | 오늘 포인트 지급 한도(`AppConfig`로 관리, 기본 20)에 도달했는지 여부. `true`면 유효 탭이 계속 쌓여도 오늘은 더 이상 포인트가 지급되지 않음 |
| boxProgressTapCount | Long | 처리 후 현재 상자 세션의 진행 탭 수 |
| nextBoxRequiredTapCount | Integer | 처리 후 다음 상자 획득에 필요한 누적 탭 수(절대값). 이번 배치에서 상자가 드롭됐다면 새로 뽑힌 다음 목표치가 반영됨 |

```json
{
  "success": true,
  "data": {
    "acceptedCount": 87,
    "validTapCount": 245,
    "pointsAwarded": 1,
    "boxesDropped": 0,
    "balance": 42,
    "pointDailyCapReached": false,
    "boxProgressTapCount": 162,
    "nextBoxRequiredTapCount": 280
  }
}
```

**멱등 재전송 시 응답 예시** (같은 `tapSessionId` + `sequence` 재요청 — 재지급 없이 잔액 스냅샷만 반환. `validTapCount`는 오늘 누적값을 다시 조회해서 반환하지만, `pointDailyCapReached`는 이 경로에서는 재조회하지 않고 항상 `false`로 고정 반환됨. `boxProgressTapCount`/`nextBoxRequiredTapCount`는 현재 상자 세션 스냅샷을 다시 조회해서 반환함)

```json
{
  "success": true,
  "data": {
    "acceptedCount": 87,
    "validTapCount": 245,
    "pointsAwarded": 0,
    "boxesDropped": 0,
    "balance": 42,
    "pointDailyCapReached": false,
    "boxProgressTapCount": 162,
    "nextBoxRequiredTapCount": 280
  }
}
```
