# BEA-308 SYSTEM_RANKING_BOOST

Approved requirements: retain RANK_CHANGE type, preferences, campaign, SENT cooldown, delivery table and Toss dispatch; leave ordinary shouldSend unchanged. A dedicated preparation path permits only an audited global 1 -> 2 transition of the pre-boost real-user leader. Real-user leader means ACTIVE, positive score, not in the current internal list or the season's historical boost recipients.

RankingEntry.score remains the public effective score, with rankingBoostScore stored separately. updateScore receives the real score and computes real + boost. Active projection and finalizing backfill preserve boost, including entries with no real taps. No tap rows/events, progress, point rewards or abuse inputs are written.

Read one coherent app_config JSON policy directly on every tick, fail closed on missing/invalid/unavailable data: ranking.systemBoost.policy = {enabled:false, internalUserIds:[], minimumLeaderScore:1000, minIncrement:200, maxIncrement:500}. Thresholds are operational values, not fixed conditions. Do not register this key in TapConfigSeeder. A code rollout gate returns false until BEA-296 reward exclusion and close-window integration are verified. A testable close-window boundary is retained; no time guard enforced yet.

Daily persisted plan: unique KST date, random five-minute slot in [18:00,22:00), chosen once and retained across restarts. After the target time, execute once within the window. At/after 22:00 mark expired; never catch up yesterday. Short transaction acquires the weekly season advisory transaction lock (same ordering as rollover), then daily row lock. Select lowest effective-score ACTIVE internal user, missing entry = zero, ties UUID text ascending. Read DB leader, skip if missing/under threshold or selected user already above leader; target = leader score + inclusive random increment. Apply only an upward change. Optimistic versions protect concurrent real tap projection; failed transaction retries the same daily plan on the next tick.

The run row is durable audit and outbox: date, scheduled instant, status, season, selected user, leader, real score, previous/target score, before/after boost, increment, pre/post leader global rank, policy snapshot, applied instant, skip reason, notification delivery ID, dispatch claim time. APPLIED audit is never reclassified/removed on configuration changes. System event reason is SYSTEM_RANKING_BOOST. Reward exclusion contract returns current internal IDs UNION APPLIED recipients for the requested season, fails closed if policy cannot be read; no reward payout is implemented. Existing display final_rank is not repurposed as reward rank.

Prepare notification in the boost transaction using a date/season/user dedupe key. Only exact global 1 -> 2, consent + enabled, configured campaign and inactive existing SENT cooldown are eligible. Post-commit dispatch and pending-outbox recovery reuse NotificationDeliveryService. Claim dispatch in a short DB transaction before sending; unknown/crashed external sends are not automatically resent (Toss has no verified idempotency contract); retain audit for manual review. Existing Redis event and periodic reconciliation recover cache failures, never roll back committed boost.

Kill switch stops new applications and unclaimed sends; it does not revert applied scores. No whitelist, no reward payout, no admin API, no production DDL/deploy/activation. Default rollout gate stays closed regardless of config. Integration tests open it only with a test double.
